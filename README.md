# — Практична робота 6 

Цей проект є модернізацією моїх попередніх лабораторних робіт. Головна мета цієї роботи — повністю очистити бізнес-логіку програми від консольного введення/виведення (Console.ReadLine/WriteLine) та перевести зберігання об'єктів на динамічну колекцію List<T>.

## Що конкретно я зробив у Lab-6:

1. **Перейшов на List<T>:** Усі об'єкти моїх дронів тепер зберігаються всередині динамічної колекції `List<Drone>`. Усі операції (додавання, видалення об'єктів, пошук за ID) реалізовані через стандартні вбудовані методи цієї колекції.
2. **Ізолював логіку від консолі:** Я повністю прибрав `Console.WriteLine` та `Console.ReadLine` із класу `DroneManager`. Тепер цей клас працює з "чистими" даними.
3. **Додав нові аналітичні методи:**
   * `GetReadyDronesCount()` — циклом перебирає список і повертає точну кількість дронів, які готові до вильоту (мають відповідний статус).
   * `GetFastestDrone()` — шукає в колекції об'єкт із найбільшою максимальною швидкістю та повертає його.
4. **Написав новий тест-клас:** У тестовий проект я додав клас `DroneManagerTests.cs`, який автоматично перевіряє роботу мого списку та нових методів аналітики без запуску консолі.

## Результати аналізу Code Coverage:
Тести покривають логіку класу `Drone` на 72,6%, а логіку списку `DroneManager` — на 91,2%. Клас `Program` має 0% покриття, що є правильним, оскільки консольний інтерфейс та ввід-вивід за правилами архітектури не підлягають модульному юніт-тестуванню.
